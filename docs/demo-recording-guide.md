# 5 分钟演示视频录制手册

> 分镜骨架见 `docs/articles/00-demo-script.md`;本手册是录制执行版:逐字旁白、时间轴、录屏设置、剪辑提示。**照着读就能录。**

## 录制前准备(30 分钟)

```bash
# 1. 起服务(新开终端)
python main.py
# 2. 起前端(新开终端)
streamlit run frontend/app.py
# 3. 打开浏览器页面备用:
#    - http://localhost:8501        (前端,主画面)
#    - http://localhost:8000/docs   (Swagger,镜头 3 闪过用)
#    - 仓库的报告文件(编辑器里打开 2026-07-30 实验报告,镜头 5 用)
```

**录屏设置**:1080p / 30fps;录制区域=全屏;麦克风先录 10 秒试听(底噪>空调声就换个房间);浏览器缩放 110%(观众看得清字);关掉所有通知(勿扰模式)。
**工具**:OBS(免费)或 QuickTime(macOS 自带);剪辑用剪映即可。
**预演**:正式录之前**完整过一遍**——尤其是问答环节,确认索引在、能出答案、有引用。(若索引为空:先在前端传一篇 `data/cmrc_docs/` 里的 md,或按 README 复现链制备。)

## 时间轴与逐字旁白

### 镜头 0 · 开场(0:00-0:15)| 画面:前端首页

> "这是一个生产级的中文 RAG 问答系统。它的特点不是功能多——是每一个功能都有独立开关、都有 A/B 归因数据,包括几个我证明无效之后如实写进报告的实验。接下来五分钟,我会跑给你看。"

### 镜头 1 · 跑起来(0:15-0:50)| 画面:两个终端 + 浏览器

> "启动很普通:一个 FastAPI 服务,一个 Streamlit 前端。值得注意的是依赖——全部由 uv.lock 锁定,Python 版本也锁了。也就是说任何人 clone 这个仓库,装出来的环境和我现在跑的逐包一致。embedding 和重排是两个本地模型,不花 API 钱、数据不出机器;LLM 走 OpenAI 兼容端点,可以一键换。"

*操作:指一下终端里滚动的启动日志,切到浏览器前端。*

### 镜头 2 · 问答 + 引用(0:50-2:00)| 画面:前端对话框(主镜头)

**问**:"范廷颂哪一年被任命为主教?"

> "看流式输出——第一个字是秒出的。这里有个设计叫投机流式:答案先逐字吐给你,忠实度校验在流结束后才跑。校验不通过,会再推一条更正事件。相当于直播,不是录播——代价是大约 3% 的情况下,你会先看到一秒未校验的答案。这个代价我在文档里是明码标价的。"

*等答案出完,鼠标悬停/点击引用标记。*

> "答案后面的引用标记:每个论断回溯到源文档的具体分块,零在线 LLM——用 claim 和 chunk 的 embedding 余弦关联做的。"

**再问一个语料里没有的问题**(如:"OpenAI 最新发布的模型是什么?"):

> "问一个知识库里没有的。它会说不知道,而不是编一个。忠实度 0.99 这个数字,直观感受就是这个。"

### 镜头 3 · 引擎盖(2:00-2:50)| 画面:Swagger(/docs)+ 日志

> "一次常规问答,在线 LLM 调用只有两次:生成,加忠实度裁判。检索这一整段——五路并行召回、RRF 融合、本地重排、膝点截断——全是零 LLM。这是系统的设计红线:新特性想上线,先证明它不往热路径加 LLM 调用。效果是延迟从最早的 42 秒压到了 5 秒左右。"

*操作:快速滚一下 /api/chat 的 schema 或日志里的阶段耗时。*

### 镜头 4 · Agentic 开关(2:50-3:40)| 画面:前端(或配置)

> "复杂问题还有一条 Agentic 路径:一个零依赖手写的 ReAct 状态机,agent 自己决定检索什么、要不要拆解问题、什么时候停。最有意思的是'什么时候停'——我花了三轮迭代:前两轮加提示词、让信号可见,finish 率反而更差;第三轮我得出结论,提示词管不住 LLM 的停止决策,改用零 LLM 的证据硬门控,finish 率从 33% 到了 93%。这段故事我单独写了一篇文章。"

*操作:问一个多跳问题(如"范廷颂担任总主教的那个教区在哪里?"),展示答案。*

### 镜头 5 · 数字怎么来的(3:40-4:40)| 画面:编辑器里的实验报告(关键镜头)

> "最后也是最重要的:这些数字怎么来的。300 题的 CMRC 全量评测,300 题全部跑通、零失败。"

*滚动报告,停在 A/B 表格。*

> "每一次优化我都做成受控实验。比如这次零 LLM 化:同索引、同题、同模型,只换代码——延迟砍半,质量方向全正。"

*翻到开放项/无效结果段落。*

> "但这份报告里还有另一面:Graph RAG 的类型化升级,F1 −0.004,我把它回退了;生成侧有两轮 prompt 实验是阴性的,原样记录。**一个敢写无效结果的项目,它的有效结果才值得相信。** 这是我做这个项目最想传达的工程态度。"

### 镜头 6 · 收尾(4:40-5:00)| 画面:README 复现链小节

> "复现链是闭环的:README 里四个命令,从索引制备到评测复现,全程文档化。目标是——任何人 clone 之后,能复现你刚看到的每一个数字。谢谢。"

## 剪辑提示

- 问答等待超过 3 秒的片段剪到 1.5 倍速(保留流式逐字的观感,别全剪掉——逐字就是卖点);
- 镜头 5 的报告画面给足停留时间,数字要让人看清;
- 字幕:关键数字上屏幕字卡(42.6s→5s / finish 33%→93% / 300/300 零失败 / F1 0.633);
- 片尾卡:仓库地址 + "所有数字可复现"。
- 总长控制在 5 分钟内;超时先剪镜头 3。

## 翻车预案(录到一半出问题时说的话)

| 状况 | 现场话术(别慌,这也是素材) |
|---|---|
| 问题没答出来/答错 | "正好——看,它没有编一个看似合理的答案。我们看它给的引用和忠实度标记……" |
| 服务起不来 | 切到预录的截图/上次录好的片段,旁白照常;事后补录 |
| 前端卡住 | 刷新,旁白:"真实系统都会有边界状况,所以每个特性都有降级路径" |
| 超时太多 | 换问简单的题;后期加速 |
