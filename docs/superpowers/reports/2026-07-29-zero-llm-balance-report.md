## 1. 背景：目标修正与三个缺口

本次工作前对齐了修正后的项目目标（已写入 CLAUDE.md）：

- 评测分数是目标，不是副产品——**追求优秀水平**；
- **性能与效果双向均衡**：既不为效果忍非常慢，也不为效率牺牲质量。两个方向都是红线。

对照目标摸底发现三个缺口：

1. **7/28 的零 LLM 化（CRAG 门控/分级 + multi_query 精简）没有验证报告**——按新红线，"没为效率牺牲质量"需要数据证明，当时没有；
2. **gate 基线过期**：质量门守的是 2026-07-26 的 n=100 旧基线（F1 0.6905），7/28 复刷中断在 128/130 题；
3. **复现链约 70% 可跑通**：干净机器首跑崩溃（强制 HF 离线）、README 无索引制备步骤、`run_eval.py` 默认数据集未入库。

另有两个报告自己开出的方子未落地：F13 finish 率持续 <50%（需硬门控）、分解路径图检索 LLM 实体回退是分解延迟主因（需零 LLM 化）。

## 3. 核心验证：零 LLM 化没有牺牲质量（A/B 对照）

**方法**：同索引（300 题语料 chroma）、同题（300 题集前 60 题切片）、同 provider（deepseek），只换代码——
- BEFORE：`bb205a4`（LLM 版 CRAG 门控/分级 + LLM multi_query 改写）；
- AFTER：当前代码（零 LLM 化 + F13 硬门控 + 图 fast_only；后两者在 full 模式下仅影响多跳子集）。

| 指标 | BEFORE | AFTER | Δ |
|---|---|---|---|
| 检索 hit / coverage | 0.983 / 0.983 | **1.000 / 1.000** | +0.017 |
| 端到端 F1 | 0.547 | **0.577** | +0.030 |
| 端到端 EM | 0.083 | **0.136** | +0.052 |
| 端到端 hit | 0.750 | **0.780** | +0.030 |
| 短答案 F1 | 0.590 | 0.594 | +0.003 |
| 忠实度 | 0.979 | 0.962 | −0.017 |
| 重生成率 | 1.7% | 3.4% | +1.7pp |
| **平均延迟** | **7533ms** | **3747ms** | **−50%** |

**结论**：延迟砍半的同时，检索/端到端指标全部正向、忠实度在抖动带内微降（仍高于 0.9 优秀线）。严格表述：n=60 下 ±0.05 属 LLM 非确定性方差，质量应读作**「无显著差异、方向全正」**；延迟 −50% 是结构性收益（摘除热路径 LLM 调用）。"不为效率牺牲性能"的红线守住且超出。

**诚实记录**：忠实度 −0.017 与重生成率 +1.7pp 方向相反于"无损"叙事，列此备查；两者都在单run方差内，但若后续 qwen 口径复现同向偏移，需排查零 LLM 分级阈值（sigmoid 0.5/0.3）是否偏松。

## 4. F13 硬门控：finish 率开放项修复

**机制**：search/decompose 后，累积证据按 rerank 分数降序送 CRAG（零 LLM，top1 sigmoid 判级），`correct` 即强制结束循环（`stop_reason=evidence_sufficient`）——停止权从"LLM 自觉"移交"证据充分度阈值"。无真实 rerank 分数（如 decompose 的纯 RRF 结果）时不启用，避免 CRAG「无分数默认通过」误判。

**15 题多跳切片**（同集历史快照对比）：

| 指标 | 历史 F13 最佳（v3b，prompt 信号版） | 硬门控版 |
|---|---|---|
| finish 率 | 53%（8/15 agent_done） | **93%（14/15 evidence_sufficient）** |
| 平均步数 | 3.6 | **1.53** |
| 检索 hit | 0.80（四轮迭代未动） | **0.93** |
| e2e F1 / EM | 0.291 / 0 | **0.566 / 0.133** |
| 平均延迟 | — | 5.9s |

**机制解释**：早停使证据池不再被重复 search 污染，收尾重排的 top_k 更干净——检索 hit 从 0.80 升到 0.93 是 F1 跳升的主驱动。

**诚实记录**：n=15，单次运行，±5pp 内无统计意义；F1 0.291→0.566 的幅度超出方差，但含混血因素（语料扩至 165 篇 + 7/28 CRAG 精简 + 硬门控 + 图 fast_only 同时生效），无法单独归因于硬门控。README 核心叙事表已从「finish 率 <50%（诚实开放项）」更新为「93%（已修复）」。

## 5. 300 题全量基线回填

2026-07-29 复刷：**300/300 零失败**（7/28 为 128/130、7/26 qwen 为 297/300，本次首次全绿）。

| 维度 | 新基线（n=300, deepseek） | 旧基线（n=100, 7/26） |
|---|---|---|
| 检索 hit / coverage | 1.00 / 1.00 | 0.99 / 0.99 |
| 忠实度 | 0.986 | 0.990 |
| 端到端 F1 / EM / hit | 0.600 / 0.143 / 0.75 | 0.691 / 0.32 / 0.84 |
| 短答案 F1 / EM | 0.610 / 0.167 | 0.640 / 0.27 |
| 平均引用 | 0.91 | 0.83 |
| 平均延迟 | **4.5s** | 7.1s（−37%） |

**F1/EM 低于旧基线不是代码退化，是数据集扩容稀释**：旧基线为 100 题精选集；同一次 300 题运行中，前 128 题（7/28 中断点）均值 F1 0.735，后 172 题约 0.50——题间难度本身不均。正确做法即本次操作：gate 基线换成 300 题全量口径，使未来比对同集可比。gate 自检（full 模式）PASS。

**当前水位自评**：检索饱和（1.0）、忠实度优秀（0.986）、延迟优秀（4.5s）；**端到端 F1 0.60 是主要短板，瓶颈在生成侧**（答案措辞与 gold span 的词法重合度，此前两轮生成侧 prompt 实验已阴性，短期无已知空间——如实列为开放项而非待办）。
