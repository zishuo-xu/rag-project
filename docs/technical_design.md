## 1. 系统级设计原则

五条原则,后续每个设计决定都能追溯到其中一条或多条:

| 原则 | 含义 | 反例(我们拒绝的做法) |
|---|---|---|
| **默认路径延迟中性** | 新特性不得往热路径加在线 LLM 调用;重活转移到索引期 | 为了"更智能"在每次查询加一次 LLM 改写 |
| **零 LLM 优先** | 判断类任务先用模型分数/规则;LLM 只用在生成与裁判两处刀刃上 | 用 LLM 做门控、分级、实体匹配这类可分数化的判断 |
| **优雅降级** | 每个可选特性:开关 → 捕获异常 → 回退基线行为 → 记日志;绝不让可选特性 500 整个请求 | 特性失败即请求失败 |
| **契约单一事实源** | 同一语义量只有一处定义/一处校准;下游读契约不读实现 | 裁判和生成器各自截断上下文 |
| **诚实遥测** | 不确定就标"未知",负结果如实落盘;遥测字段进 dataclass 不进 ad-hoc 日志 | 解析失败假装成功;悄悄丢弃失败样本 |

**设计检验方法**:任何新特性提案,先回答三个问题——热路径加几次 LLM 调用?失败时降级到什么?哪个遥测字段能证明它有效?答不上来的提案不合并。

## 2. 检索管道:为什么是固定七阶段

```
门控 → 查询变换 → 多路并行召回 → RRF 融合 → 重排 → CRAG 分级 → 补救
```

**决定:主管道是固定阶段序列,不是动态编排。** 备选方案是"让 LLM 决定检索流程"(即 Agentic)。我们让两条路径并存、且 Agentic 默认关:固定管道给**可预测的延迟和可归因的指标**(每次 A/B 都能定位到具体阶段),Agentic 给复杂查询的上限,异常即降级回固定管道。教学样板的可复现性要求主管道必须是确定性的。

**五路并行召回(dense/sparse/graph/parent-child/summary)**,线程池 `recall_max_workers=6`:

- 为什么并行而非串行:五路互不依赖,墙钟 = max(各路) 而非 sum;
- 为什么是这五路:dense 保语义召回、sparse(BM25+jieba)保精确词命中(中文专名/数字)、graph 保关系链、parent-child 保"小块命中、大块阅读"、summary 保篇章级粗召回。**每一路有自己不可替代的失败模式**,删任何一路都有对应的 bad case;
- 通道失败不阻断:`future.result()` 异常只 warn,该路记空——单路挂掉(如图谱未构建)系统继续工作。

**RRF 融合,k=60**。备选是加权分数融合,被否的理由:各通道分数量纲不同(dense 余弦 ∈[0,1]、BM25 无上界),归一化本身引入调参面;RRF 只用名次、无量纲问题、k=60 是文献标准默认。去重按 chunk_id——graph 通道的文档用 `graph:` 前缀 id,避免与真实分块互覆盖(这是一个实测踩过的坑)。

**重排预筛契约(top-N=20)**。cross-encoder 全量打分 ~3s(CPU 最大单点)。设计决定:**只对 RRF 头部 top-20 精排**,依据是一条被评测持续验证的不变式——*答案恒在 RRF 融合分的头部*(`answer_in_top_context` 实测 1.0)。契约写明:任何改动若破坏"融合分头部含答案",预筛才需要重议。这条不变式是 3s→1s 优化的全部合法性来源。

**Autocut 膝点截断(F1)**。固定 TopK 的两难:k 大送噪声(k=8 时 docs→LLM 8 篇),k 小丢答案。Kneedle 在 rerank 分数曲线的膝点截断,下界 `autocut_min_docs=2`、上界 `retrieval_top_k`(不扩容)。实测入 LLM 上下文 61.9→6.0 篇/题。设计约束:截断只发生在 rerank **之后**(依赖分数单调),与重排阶段强耦合,不可独立移植。

## 3. 排序与充分性:分数即判据

**核心设计:reranker 的分数不仅用于排序,还是三个下游判断的唯一输入**——CRAG 分级、F13 硬门控、(部分地)补救触发。一次打分,四处复用,零新增计算。

**CRAG 分级:sigmoid(top1) 判三级**。`p≥0.5` correct、`p<0.3` incorrect、中间 ambiguous。

- 为什么 sigmoid 而非原始分:cross-encoder logit 无直观阈值,sigmoid 映射到 (0,1) 后阈值可解释;
- 为什么只看 top1:分级回答的是"最好的证据够不够",不是"平均够不够";
- **耦合警告(写进文档的维护契约)**:0.5/0.3 是按 `bge-reranker-base` 的分数分布校准的。换 reranker 必须重校准这两个阈值,否则出现"忠实答案被判 incorrect → 无谓重生成"或反向漏判。这不是 bug,是分数判据设计的固有成本,显式登记。

**数字型问题另有零 LLM 校验**(`validate_numeric_answer`):问年份/数量时,检查上下文是否含数字信息,否则直接判 incorrect 触发补救——规则能判的不动用分数。

## 4. 延迟治理:预算契约

**`Deadline`:每条查询一个全局预算(`latency_budget_ms=25000`)**,在管道入口创建,沿 `RetrievalResult.deadline` 透传到生成层。可选阶段执行前调 `deadline.check_skip(stage)`,超预算即跳过并记入 `budget_skipped` 列表。

设计要点:

- **预算是熔断离群尾,不是压均值**。典型路径 ~4.5s,预算 25s 几乎从不触发(评测 0/15、0/300)——这是对的:它防的是 486s 那种尾部灾难(治理前实测),不是日常。预算设得比典型值紧会误伤正常请求,宽到无边等于没有;
- **跳过的是可选质量增量,不是核心链路**:F2 迭代补召、F3 重生成可跳;主召回、主生成不可跳。跳过后系统输出"质量略降但正确"的结果,而不是超时;
- **answer_max_tokens=1024** 封住生成长度离群尾(原无界)。

**F8 投机流式的时序设计**:忠实度校验放在**流耗尽之后**,不与生成并发、不阻塞首 token。为什么不做边流边判:claim 抽取需要完整答案(半句判不了),且一次调用判全部 claim 最省。代价是一个诚实的错误曝光窗口(见 §5)。

## 5. 质量契约:忠实度的三个设计决定

**决定一:单一事实源。** 裁判和生成器使用**同一份格式化上下文**(函数参数显式传递,不是各自从状态里取)。历史教训:旧版裁判自行截断上下文,导致答案明明忠实、裁判却看不到依据 → 假阳性重生成。对齐后这类误触发归零。*契约:任何需要"依据"的判断,依据必须与生成依据同址同源。*(另一起同源事故:上下文压缩的词级抽句 bug 把答案依据压没了,忠实度准确率 0.61→0.95、错误拒答 11→0——压缩与校验必须语义对齐。)

**决定二:有界纠正。** `faithfulness_threshold=0.7`(被支撑 claim 占比)、`faithfulness_max_regen=1`。不忠实 → 严格 prompt 重生成(显式允许拒答)→ 再判一次,**最多一轮**。不做"直到忠实为止"的循环:无限循环用延迟不确定性换质量幻觉,而严格 prompt 的一次重生成通过率已经很高(重生成率仅 1.7%,触发后几乎全通过)。一轮后仍不忠实 → 带 `faithful=False` 元信息如实返回。**系统宁可承认失败,不假装成功。**

**决定三:投机交付(F8)。** 流式路径先吐答案、流末校验、不忠实追加 `correction` 事件。保证是"停留在页面上的最终版本经过校验",**不**保证"第一眼经过校验"——3% 概率、约 1 秒的错误曝光窗口是这个设计的明码标价。适用域:对话产品可接受;强合规场景应回退非流式阻塞路径(`use_speculative_streaming=False`)。两条路径共用同一个 `regen_until_faithful` 循环体——行为一致性由代码结构保证,不靠两处各写一遍。

## 6. 缓存:成本转移而非成本消除

三级,各管一段:

| 级 | 对象 | 键 | 设计要点 |
|---|---|---|---|
| 语义响应缓存 | 整个回答 | query embedding,余弦 ≥ `cache_threshold=0.92` | 命中即零 LLM;阈值 0.92 宁缺毋滥——错配一个答案的代价远大于多算一次 |
| embedding 缓存 | query 编码 | query 文本 | 省本地编码(多查询变体场景收益明显) |
| rerank 缓存 | (query, chunk) 分数 | 对 | 重排是本地最大计算,同 chunk 复现率高 |

**更根本的成本转移原则:索引期 LLM vs 在线 LLM。** F6a 上下文增强、L1 摘要、图谱抽取全在索引期执行(一次性 ~3700 次调用),在线增量零 LLM。这是"默认路径延迟中性"的实现手段:允许花 LLM,但只许花在没人等待的时间里。复现代价诚实标注:无 key 复现得到"无增强版"索引,端到端数字会偏低,README 写明。

## 7. Graph RAG:一次 null 结果如何影响设计

**当前设计:零 LLM jieba 共现图(21856 节点/106483 边,1 秒重建)。** 这个设计是一次失败实验的产物:

1. 初版共现图 → 升级为 LLM 类型化三元组(人/作品/地点/职位 + chunk 溯源),结构能力明确升级;
2. A/B 结果:F1 **−0.004**(波动带内),延迟 +12%,重建 3.6h;
3. 决策:回退共现图。理由有二——检索收益未兑现(三连跑稳定),且 3.6h 重建与"可复现"硬目标冲突(每个 clone 者都要付同样成本);
4. 诚实记录:类型化版本保留为可选路径(`rebuild_graph_typed.py`),报告写明"关系无类型化、实体含 jieba 噪声,但检索仍可用"。

**派生设计:fast-first 双路实体抽取。** 图节点关键词匹配(零 LLM)优先,未命中才回退 LLM 抽取;**分解路径子问题 `fast_only` 不回退**(`decompose_graph_fast_only=True`)——子问题成倍放大回退调用,是分解延迟主因,且零命中说明图通道对该子问题无增益,dense/sparse 兜底即可。主路径保留回退(单查询,成本可控)。

**弱边治理**:分类学边(属于/是一种…)单条是事实、串联成多跳路径会桥接无关联实体。`find_path` 优先返回"剔除弱边后的纯实义最短路径",多跳且仅靠弱边连通时标 `weak_only` 供前端诚实标注。

## 8. Agentic:停止权的归属设计

手写 ReAct 状态机(约 200 行,零 LangGraph 依赖)。两个设计决定:

**决定一:工具 = 现有阶段的复用,agent 只做编排。** `search` 复用 `pipeline.search` 复合原语,`decompose` 复用 F6b,`grade` 复用 CRAG。agent 不引入任何新检索能力——它的价值是**选择**,不是执行。副产品:工具全可离线 mock 测试。

**决定二:停止权外置(硬门控)。** 三轮迭代的结论(详见 [F13 文章](./articles/02-f13-finish-rate-hard-gate.md)):prompt 能校正工具选择偏好,校正不了停止决策("信号可见 ≠ 决策控制",v3 让信号完全可见后 finish 率不升反降:40%/33%)。最终设计:search/decompose 后,累积证据按 rerank 分降序送 CRAG,`correct` 即强制 break(`stop_reason=evidence_sufficient`)。零新增 LLM(复用 §3 的分数判据),finish 率 33-53%→93%,平均步数 3.6→1.53。

**护栏分层**(从软到硬):重复查询警告(observation 注入)→ 连续 2 次零新增强制收敛(`converged`)→ 证据充分硬门控(`evidence_sufficient`)→ max_steps=4 硬上限 → 决策解析失败即停(`decision_error`)→ 整体异常/空证据降级回七阶段管道。每一层都有独立的 stop_reason,遥测可区分**为什么停的**——这是调优能进行的前提。

## 9. 评估体系:容差、口径与分层

**分层**(各层统计功效不同,混用即自欺):

| 层 | n | 职责 | 判定 |
|---|---|---|---|
| 零 LLM 检索评测 | 300 | 检索管道回归 | 秒级,每次改检索必跑 |
| 50 题快速切片 | 50(步长 6 确定性抽样) | 日常 A/B | 容差 ±0.11,负结果不下强结论 |
| 多跳/多轮切片 | 15 / 12 | 专项 | ±5pp 内无统计意义,只作方向信号 |
| 全量基线 | 300 | 发版 + gate 重定 | 容差 ±0.05 |

**容差设计**。质量门对 F1 设 ±0.05、hit ±0.08 的相对基线容差——吸收 LLM 非确定性抖动。无容差 = 误报工厂(每次 push 都在"退化"),无基线 = 摆设。`chain_health` 另设绝对判定:任何一题抛异常即 fail(全链路不崩是底线,不容"抖动"解释)。

**口径纪律**。评测输出落盘记录 `provider`;基线文件标注来源跑批;跨 provider 不做 gate 退化比对(实测 deepseek↔qwen F1 差 0.11,比任何代码改动都大)。一个差点骗过自己的陷阱:300 题 F1 0.600 < 旧 n=100 基线 0.691,查因是数据集扩容稀释(前 128 题 F1 0.735,后 172 题 ~0.50)——**换集必须重定基线**,已固化进流程。

**gate 语义**:smoke 层只查绝对阈值(检索 hit≥0.8、延迟≤30s、链路健康)——这些对生成措辞抖动不敏感,适合每次 push;full 层叠加相对基线退化,发版前手动。

## 10. 优雅降级:统一模式

所有可选特性共享同一形状:

```python
if settings.use_<feature>:
    try:
        result = <feature_logic>()
    except Exception as e:
        logger.warning(f"<feature> 失败,降级: {e}")
        result = <baseline_behavior>
```
