模块按「查询改写 → 多路召回 → 结果融合 → 精排」的线性阶段组织：
- `query_transform.py` 提供 `QueryTransformer`，基于 LangChain ChatOpenAI + StrOutputParser 实现 Multi-Query 与 HyDE 两种改写策略，作为检索入口。
- 召回层由三个独立检索器组成，均通过依赖注入接收 `app.ingestion.indexer.HierarchicalIndexer`（稠密走 ChromaDB 余弦相似度，稀疏走 `rank_bm25.BM25Okapi` + jieba 分词，图检索走 `app.ingestion.graph_extractor.KnowledgeGraphBuilder`）；每个检索器同时暴露 `retrieve` 与 `retrieve_with_scores` 两套接口。
- `fusion.py` 提供无参函数 `reciprocal_rank_fusion` 与 `weighted_fusion`，以 `chunk_id`/内容哈希为文档去重键，将多路 `List[Document]` 合并并写入 `rrf_score`/`fusion_score` 元数据。
- `reranker.py` 的 `Reranker` 使用 `sentence_transformers.CrossEncoder` 对融合后的候选做细粒度打分，输出 `rerank_score`。
- `graph_retriever.py` 的 `GraphRetriever` 通过 LLM 抽取实体后调用 `KnowledgeGraphBuilder.get_entity_relations` / `get_subgraph`，并以自然语言三元组形式包装为 `Document`，作为第四路召回参与融合。
- 所有外部依赖（OpenAI、BM25、CrossEncoder、配置）均通过 `config.get_settings()` 或构造函数参数注入，避免在模块内硬编码实例，便于上层编排不同召回组合。
