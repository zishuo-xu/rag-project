# RAG 技术详解

## 什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种结合信息检索和文本生成的技术框架。它通过从外部知识库中检索相关文档，将检索结果作为上下文传递给大语言模型（LLM），从而增强模型的回答能力。

RAG 的核心优势：
- 减少幻觉：基于真实文档回答，而非模型记忆
- 知识可更新：只需更新知识库，无需重新训练模型
- 可溯源：回答可以标注信息来源
- 领域适配：通过导入领域文档实现专业化

## RAG 系统架构

一个典型的 RAG 系统包含以下组件：

### 1. 文档处理管道（Ingestion Pipeline）
- 文档加载：支持 PDF、Word、Markdown、网页等格式
- 文本分块：将长文档切分为适当大小的片段
- 向量化：使用 Embedding 模型将文本转为向量
- 索引存储：将向量存入向量数据库

### 2. 检索模块（Retrieval）
- 稠密检索：基于向量相似度的语义搜索
- 稀疏检索：基于 BM25 的关键词匹配
- 混合检索：结合稠密和稀疏检索的优势
- 重排序：使用 Cross-Encoder 对候选结果精排

### 3. 生成模块（Generation）
- Prompt 构建：将检索结果组织为上下文
- LLM 生成：基于上下文生成回答
- 后处理：格式化、引用标注

## 分块策略

文本分块是 RAG 系统中的关键环节，直接影响检索质量。

### 递归字符分块
按层级分隔符（段落 > 句子 > 字符）递归切分，保持语义完整性。

### 语义分块
基于相邻文本的 embedding 相似度检测语义边界，在语义跳变处切分。适合主题频繁变化的文档。

### 分块参数选择
- chunk_size：通常 256-1024 字符，取决于文档类型
- chunk_overlap：通常 10%-20%，保证上下文连贯
- 过小：语义不完整，检索噪声大
- 过大：包含多个主题，检索精度低

## 多路召回与融合

### 为什么需要多路召回
单一检索方式各有局限：
- 向量检索擅长语义匹配，但对精确术语匹配较弱
- BM25 擅长关键词精确匹配，但无法理解同义词

### RRF（Reciprocal Rank Fusion）
RRF 是一种基于排名的融合策略：
- 公式：score(d) = Σ 1/(k + rank_i(d))
- k 通常取 60
- 优势：不依赖原始分数，仅利用排名信息
- 多路都命中的文档获得更高分数

## 重排序（Reranking）

### Bi-Encoder vs Cross-Encoder
- Bi-Encoder：query 和 document 分别编码，计算向量相似度。速度快，适合大规模初筛。
- Cross-Encoder：query 和 document 拼接后一起输入模型。精度高，但速度慢，适合对少量候选精排。

### 典型流程
1. Bi-Encoder 从百万文档中召回 top-100
2. Cross-Encoder 对 top-100 精排，选出 top-5
3. 将 top-5 送入 LLM 生成回答

## 查询优化

### Multi-Query
生成多个查询变体，扩大召回面。适合用户问题表述模糊的场景。

### HyDE（Hypothetical Document Embeddings）
先让 LLM 生成假设性回答，用其 embedding 做检索。因为假设回答在语义空间中更接近真实文档。

## 评估体系

### RAGAS 框架
- Faithfulness（忠实度）：回答是否忠于检索内容
- Answer Relevancy（答案相关性）：回答与问题的匹配度
- Context Precision（上下文精确度）：相关文档是否排在前面
- Context Recall（上下文召回率）：是否检索到了所有相关信息

### 评估最佳实践
- 构建领域特定的测试集
- 定期评估，监控质量变化
- 对比不同策略的效果（A/B 测试）
